# HC-05 波特率配置工具（AT 模式，无需 USB-TTL）

给 HC-05 / HC-05D 把串口从出厂 9600 改成 115200 的一次性工具。
用 FPGA 自己当串口助手，不需要买 CH340。

---

## 1. 为什么需要

全链路（`feature/bt-in` 与 `feature/bt-out`）统一是 **115200 8N1**，分频 `DIV=234`。
但 HC-05 出厂是 **9600**，这个值存在模块自己的 flash 里，FPGA 改不了它。

带宽上也没法将就：`bt-out` 的遥测是 20 字节 × 30 Hz = **6000 bps**，
放在 9600 上占 62%，突发就丢帧。所以必须把模块改到 115200。

改的唯一途径是 AT 命令，而 AT 模式要求 **KEY/EN 在上电瞬间为高**。

---

## 2. 硬件前提（三条，顺序不能乱）

### 2.1 先量 TXD 电平

万用表直流档，黑笔 GND，红笔模块 **TXD**，上电、不配对、不发数据：

| 读数 | 处理 |
|---|---|
| 3.2~3.4 V | 直连 |
| 4.8~5.1 V | **必须先分压**，见下 |

5V 直连会经 FPGA 引脚的钳位二极管倒灌进 3.3V 电源轨，属于超规格运行。

分压（`1k` 串、`2k` 对地，取中间点）：

```
模块 TXD ──[1kΩ]──┬──→ FPGA 77 脚
                  │
                [2kΩ]
                  │
                 GND
```

`5 × 2/(1+2) = 3.33 V`。

### 2.2 KEY/EN 接 3.3V，且必须在模块上电**之前**就为高

用一根杜邦线把模块的 EN/KEY 接到板上 3.3V。

**为什么不能让 FPGA 的 GPIO 代劳**：FPGA 配置完成之前所有 IO 都是高阻，
这时模块已经上电采样过 KEY 了。所以只能靠硬连线或模块自带的按键。

判断进没进 AT 模式：模块 LED **慢闪（约 2 秒一次）**，不是快闪。

### 2.3 共地

FPGA 与模块必须共 GND，否则串口电平没有参考点。

## 3. 烧录

```bash
# 一条命令构建（在仓库根目录执行，产物在 gowin/at_cfg/impl/pnr/project.fs）
gw_sh gowin/at_cfg/at_cfg.tcl
```

或在 Gowin IDE 里把 `top_at_cfg` 设为顶层，文件列表：

```
rtl/uart_rx.v
rtl/bt_at_init.v
rtl/top_at_cfg.v
constraints/at_cfg.cst
constraints/at_cfg.sdc
```

命令行脚本（器件参数必须带 `-name`，否则报 "more than one device"）：

```tcl
set_device -name GW2AR-18C GW2AR-LV18QN88C8/I7
set_option -top_module top_at_cfg
add_file rtl/uart_rx.v
add_file rtl/bt_at_init.v
add_file rtl/top_at_cfg.v
add_file constraints/at_cfg.cst
add_file constraints/at_cfg.sdc
run all
```

烧 `impl/pnr/project.fs`。这个固件**不含音频链路**，只做 AT 配置。

## 4. LED 判读

板载 LED 低电平点亮，顶层 `LED_ACTIVE_LOW=1` 已反相，下表按"亮"描述。

| LED | 含义 |
|---|---|
| `led[0]` | 心跳，约 0.8 Hz 慢闪。**它不闪就说明程序没跑起来** |
| `led[1]` | 正在发送 |
| `led[2]` | 收到过任何字节 |
| `led[3]` | 收到过 `OK` |
| `led[4]` | **成功，常亮** |
| `led[5]` | 失败，约 6 Hz 快闪（重试 5 次无应答） |

发完三条命令约 1 秒内出结果。

---

## 5. 成功之后

1. **断电**
2. **拔掉 KEY→3.3V 那根线**（不拔的话每次上电都进 AT 模式，永远不出数据）
3. 重新上电
4. 烧回正常固件
5. 用网页或串口助手以 **115200** 连一次，按键应当出声

## 6. 失败排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 全灭，连 `led[0]` 都不闪 | 没烧进去 / 时钟脚不是 4 | 重新烧录 |
| 只有 `led[0]` 闪 | 一个字节都没收到 | TXD 没接、模块没供电、模块没进 AT 模式、没共地 |
| `led[2]` 亮但 `led[4]` 不亮 | 收到字节但不是 `OK` | ① 有些固件的 AT 模式用**当前数据波特率**而不是 38400 → 把 `bt_at_init.v` 的 `BAUD` 改成 9600 重新编译再试；② 回的是 `ERROR:(x)` → 指令集不同，见下 |
| `led[4]` 亮但改完还是不通 | 配置没落盘 | 断电重启一次；或命令改用 `AT+UART_DEF=115200,0,0` |

**双模芯片（HC-05D 可能是）指令集不一样**，常见的替代写法：

```
AT+BAUD=8            // 部分 HC-06 系：8 = 115200
AT+UART_DEF=115200,0,0
AT+UART=115200,0,0,0 // 部分型号多一个流控参数
```

改 `rom_byte` 命令表里 `14..33` 那 20 个字节即可，其余逻辑不用动。

## 7. 实现要点

**为什么自己写位转发器，不用 `rtl/uart_tx.v`**
`uart_tx.v` 的负责人是 `feature/bt-out`，在 `feature/bt-in` 上它还是空壳
（`tx` 恒高、`busy` 恒 0）。为了不跨分支改别人的文件，发送逻辑在 `bt_at_init.v`
里自带一套（10 位移位寄存器 + 分频计数器），只复用本分支的 `uart_rx` 收回复。

**为什么是 703 分频**
`27 MHz / 38400 = 703.125`，取 703，误差 **+0.018%**。
一帧 10 位累计偏差 `0.018% × 9.5 ≈ 0.002` 比特，采样点仍稳在比特中心。

**为什么发完配置不发 `AT+RESET`**
部分固件在 `AT+UART` 成功的**那一刻**就切到新波特率，此时再用 38400 发
`AT+RESET` 等于给模块灌噪声。断电重启效果一样且更干净——反正流程里本来就要断电。

**为什么 `owner` 那套不在这里**
本工具不接 `voice_alloc`、不碰触摸板，只发字节、只收 `OK`。
`bt_cmd_parse` 的接管逻辑完全不受影响。

## 8. 验证记录

仿真 `tb/tb_bt_at_init.v`（`iverilog -g2012`）：

```
[ OK ] 阶段A：done 拉高，仿真时间 14326 us
[ ok ] 实际发出: "AT\r\nAT+UART?\r\nAT+UART=115200,0,0\r\n"
[ OK ] 阶段B：无应答，重试 3 次后 fail 拉高（未死等）

=== ALL PASS ===
```

- 阶段 A：TB 扮演模块回 `OK`，用一只 `uart_rx` 把 DUT 的 `at_tx` 解回字节，
  与期望的 34 字节逐字节比对，**全等**。
- 阶段 B：TB 完全不回应，验证重试耗尽后置 `fail` 而不是死等。

综合（GW2AR-LV18QN88C8/I7）：**0 error，0 setup/hold 违例**，
LUT 313/20736、寄存器 150/15750，时序余量 30.7 ns。

> 综合时有一条 `WARN (PR1014)`：时钟 `clk_d` 走了通用布线资源。
> 原因是本设计没有 PLL，时钟直接从 4 脚进普通布线。27 MHz 下实测余量充足，
> 不影响功能；以后若要提速，加 `BUFG` 或 PLL 即可消除。
