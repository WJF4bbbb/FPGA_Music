# FPGA 波形工作台

在原有 Web 工作台中增加真实 FPGA 音频样本显示，支持有线 Web Serial 和 HC-05 蓝牙桥接。网页只绘制收到的完整采集帧；普通连接模式没有浏览器合成的替代波形。

## 使用

1. 给 FPGA 更新 `bitstreams/waveform-2026-11-04/` 内的新固件。Type-C 有线连接使用 `MusicSynth_Waveform_Wired.fs`，外接 HC-05 使用 `MusicSynth_Waveform_BT.fs`。UART 引脚分别为 TX/RX=69/70 和 85/77。旧固件仍可使用原状态面板，但不会输出波形。
2. 在项目根目录运行 `python -m http.server 8765 --bind 127.0.0.1`，用桌面 Chrome/Edge 打开 `http://127.0.0.1:8765/web/index.html`，点击连接串口并选择相应 COM 口。串口保持 115200、8N1。
3. Windows 蓝牙没有生成 COM 口时，改运行 `python tools/bt_bridge.py`，打开 `http://127.0.0.1:8765/web/bridge.html`。不要同时在同一端口运行静态服务器与桥接服务器。
4. 按实体触摸键或网页虚拟键，下面的“FPGA 实测波形”显示实际样本。“冻结”保留当前图，“继续”显示最新完整帧。幅度倍率用于观察小信号。

固件烧录沿用原工程的 Gowin Programmer 流程。SRAM 调试断电失效，外部 Flash 保存固件；本次交付没有自动烧录板卡。原发布目录中的既有位流保持原样。

## 显示含义

- 每次采集 512 个连续有效的 16 位有符号样本，采样率 46875 Hz。整段采样时间约 10.923 ms；图上从第一个到最后一个采样点的坐标范围为 10.901 ms。
- 每秒发起 8 次采集请求，实际更新速度取决于采集和传输是否空闲。图与图之间有采样空隙，不能作为连续录音。
- 纵轴为样本值除以 32768 的数字幅度，单位不是伏特。倍率会同步改变纵轴标注。
- 采集优先等待从负到非负的过零点；等待 256 个有效样本后自动采集，因此无声时也能收到零线。和弦的叠加波形允许自然变化。
- 1.5 秒没有完整采集帧时显示“数据已过期”。未收到首帧时提示等待新固件/波形数据。
- 观察点是 `tx_sample` 与 `mixed_valid`：功放静音门控后、I2S 帧缓存前的数字音频。它不包含 DAC、功放和扬声器的模拟回采，也不能代替对 I2S 欠载/线级时序的测量。

## FPGA 实现

`wave_capture.v` 只旁路观察音频输入，不向音频链路施加背压。单块 512×16 RAM 从采集完成到传输结束保持冻结；忙时跳过新的请求，避免采集覆盖正在发送的数据。综合映射为一个 SDPB 块 RAM。

`telemetry.v` 使用原有单个 UART。原状态包格式不变；状态请求在完整波形分包之间优先发送。每个波形分包最多 120 个采样点，CRC 逐字节计算。发送期间原状态字段保持一份一致快照。

总数据量约 9472 字节/秒（8 幅完整波形加 30 个状态包，未计字节间少量握手空隙），小于 115200/10=11520 字节/秒的理论串口吞吐上限。实际蓝牙吞吐、丢包与延迟仍需上板测量。

## 波形协议 v1

外层保持 `AA 55 | type | len | payload | CRC8`，CRC 多项式 0x07、初始值 0，覆盖 type、len 和 payload。状态类型 0x01 的 15 字节 payload 完全保留。新增波形类型 0x10：

| Payload 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u8 | 版本，固定 1 |
| 1 | u8 | bit0=过零触发；其余位为 0 |
| 2–3 | u16 LE | 采集序号，65535 后回到 0 |
| 4–5 | u16 LE | 本幅总采样点数，512 |
| 6–7 | u16 LE | 当前分包起始采样偏移 |
| 8–11 | u32 LE | 采样率，46875 |
| 12 起 | i16 LE[] | 最多 120 个连续样本 |

每幅分为偏移 0、120、240、360、480 的五包，前四包 len=252，最后一包 len=76。完整大包为 257 字节，RTL 的字节索引使用 9 位。

JS/Python 均校验版本、标志、采样率、长度、偏移、采集序号和顺序。缺包、重复、错序、元数据冲突或 CRC 错误会丢弃不完整采集；下一个偏移 0 的分包可重新开始。重连清空解析状态。SSE 使用独立的 `wave` 事件，只发布完整采集；已有未命名状态事件不变。

## 验证与复现

执行新增采集、UART、音频对照、蓝牙协议和网页/Python 检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run_waveform_checks.ps1 -Python python
```

需要同时执行原有完整整机回归时添加 `-FullRegression`。Icarus 必须与同一 OSS CAD Suite 的运行库配套。脚本会检查进程退出码和明确 PASS/FAIL 文本；Node 与 Python 不需要额外包。

重新布局布线、检查资源和时序：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_waveform.ps1 -Target wired -GowinBin "你的 Gowin IDE/bin 目录" -OutputDirectory "新的构建目录"
python tools/verify_waveform_build.py "新的构建目录" --target wired
```

蓝牙版把 target 改为 `wireless`。构建不覆盖旧目录、不执行烧录。验证器检查输入文件 SHA256、源文件清单、块 RAM 映射、零锁存器、27 MHz、Setup/Hold 违例和 TNS；只有通过的位流才进入新发布目录。

本轮已验证：

- 小深度 RTL 测试：采样使能、符号边界、触发/静音回退、冻结、复位和忙时请求。
- UART 引脚独立解码：10 个波形分包还原 1024 个已知样本，逐点一致；10 个状态包中 6 个在波形分包之间发送。
- 修改前后的真实顶层对照：1200000 个时钟、2084 个 PCM 样本完全一致，2073 个非零样本，覆盖四声部、四种音色和音量控制，同时比较每个 I2S/触摸控制输出。
- 独立 Gowin 综合后的捕获模块与官方 GW2A 原语模型仿真：512 点正常波形和 512 点静音共 1024 个 RAM 字逐项一致，读延迟正确。
- 浏览器与 Python 公共解析器均解码上述 UART 测试数据；缺包、CRC、重连、状态兼容性与 SSE 测试通过。
- 实际浏览器通过模拟串口输送 RTL 生成的 UART 字节，检查状态面板共存、真实样本绘图、冻结/继续、倍率、过期、断连清空及 390px 窄屏；没有 JavaScript 异常。
- 原整机回归检查了 22503 个外部 I2S 双声道帧，5537759 条断言通过。初次执行暴露了旧测试对默认演示模式的过期假设，已在专门测试中显式开启 `DEMO_ENABLE=1` 并重测；正式固件默认仍关闭演示模式。
