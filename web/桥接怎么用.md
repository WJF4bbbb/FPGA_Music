# 蓝牙桥接 —— Windows 建不出 COM 口时用这个

## 快速开始（可以直接照这个做）

**准备**

1. 代码：`git fetch origin && git checkout release/prelim-1104`
2. 板子烧 `bitstreams/release_prelim-1104/MusicSynth_TangNano20K.fs`（已是最新，不用改）
3. 模块和电脑配对（配对码 `1234` 或 `0000`），**保持通电**
4. 浏览器用桌面版 Chrome 或 Edge，手机和 Firefox 都不行

**第一步：先试直接连**

双击 `web/index.html` → 点"连接蓝牙串口" → 选名字带 `HC` 的 COM 口。

顶部变绿"已连接"、右边出数字 = 成了，下面不用看。

列表里没有 HC 的 COM 口，或者报"连接失败" → 走第二步。

**第二步：桥接**

```
cd /d "你的路径\FPGA_Music"
python tools/bt_bridge.py
```

屏幕会列出已配对的蓝牙设备，输入模块前面的序号回车（只有一个时自动选）。

看到 `蓝牙桥接服务已启动` 和一行网址后，浏览器打开那个网址（默认
`http://localhost:8765/web/bridge.html`）。

界面和 `index.html` 完全一样，虚拟键盘也能用。

**必须知道的**

- 板子不用重烧，代码不用改，桥接只是电脑上多跑一个 Python 进程
- 关掉命令行窗口 = 断开连接
- 同一时间只能开一个网页连它
- 没数据先看模块的灯：**快闪 = 没连上**，得先配对
- 想确认状态：浏览器开 `http://localhost:8765/info`，`"connected": true` 就对了
- 脚本只用 Python 标准库，不用 `pip install` 任何东西

## 什么时候需要

**先试 `web/index.html`**（Web Serial 直连 COM 口）。

只有在串口列表里**根本找不到 HC-05 的 COM 口**时才用这里。典型症状：

- 蓝牙配对成功、设备管理器里没有黄色感叹号
- 但设备管理器"端口"下只有 COM3/COM4，没有新端口
- 网页点"连接蓝牙串口"报"连接失败"

## 怎么用

1. 先把模块和电脑配对好（配对码 `1234` 或 `0000`）
2. 模块保持通电
3. 在 `FPGA_Music` 目录下开终端：

   ```
   python tools/bt_bridge.py
   ```

4. 脚本会自动扫描已配对的蓝牙设备并列出，让你选序号（只有一个候选时自动选）
5. 看到这段就成功了：

   ```
   蓝牙桥接服务已启动
   网页地址: http://localhost:8765/web/bridge.html
   ```

6. 浏览器打开那个地址

关掉终端窗口就停止服务。

## 为什么需要它

Windows 只在**配对那一刻**查询一次蓝牙服务列表。如果那次没查到
Serial Port（`0x1101`），之后就不会再查，也永远不创建 COM 口。

但蓝牙的 RFCOMM 通道本身是通的。这个脚本直接连通道（默认 channel 1），
把 `AA 55` 帧解析成 JSON，用 SSE 推给浏览器。

## 它不改任何东西

- 板子固件不用重烧，一个字节没动
- `index.html` / `serial.js` / `display.js` 一个字节没动
- 只是在电脑上多跑一个 Python 进程

`bridge.html` 用的是同一套 `display.js` 和 `input.js`，界面和原版完全一样，
虚拟键盘也能用（走 POST 转发到蓝牙）。

## 手动指定 / 排查

```
python tools/bt_bridge.py --scan                  # 只列出已配对设备
python tools/bt_bridge.py --addr 00:02:5B:00:FF:01  # 手动指定 MAC
python tools/bt_bridge.py --channel 1             # 换 RFCOMM 通道
python tools/bt_bridge.py --port 9000             # 换 HTTP 端口
```

连上后可以看运行状态：

```
http://localhost:8765/info
```

返回 `{"connected": true, "frames": 406, "bad_crc": 0}` 就说明正常。
`bad_crc` 一直涨说明波特率不对（板子发 115200，模块也得是 115200）。

## 只依赖标准库

不需要 `pip install` 任何东西，Python 3.8+ 自带的就够。
